# S02 — данные юнитов, валидатор и тестовая основа

15 октября 2026. Unity 6000.5.4f1. Изменения поверх исходного c038c9b и существующей локальной миграции Unity; коммит и публикация не выполнялись.

## Реализация

- `UnitDefinitionRecord` — входной формат конфигурации; `UnitDefinition` — неизменяемый снимок численных характеристик и ссылок. `UnitCatalog` проверяет записи и разрешает ссылки по стабильному ID либо старому имени для совместимости.
- `UnitInstance` хранит изменяемые данные: ID экземпляра и определения, текущее и максимальное HP, характеристики боя и cooldown. `Unit` оставлен совместимым сериализуемым типом поверх `UnitInstance`: существующие JSON поля и массивы не переименованы.
- `BattleState` создаёт независимые экземпляры для обеих сторон. Урон и временное изменение характеристик не изменяют исходный состав, определения, противника или следующий бой.
- Бой и экран отряда используют один каталог вместо двух реализаций копирования полей. При создании героя и найме/слиянии юнит получает ID экземпляра. Существующие сохранения читаются по старому полю `unit`; новые поля появляются при материализации экземпляров. Массовой перезаписи PlayerPrefs не выполнялось.
- В `Units.json` добавлены отдельные `id`, `displayName`, `role`, `faction`. Все прежние поля 16 записей сравнены с HEAD и сохранены без изменений. ID закреплены явными строками `unit.*`, не вычисляются из отображаемого имени во время игры.
- Роли текущих юнитов предварительно классифицированы по их существующему оружию и описаниям: Warrior, Archer, Mage. Фракции намеренно `Unassigned`: перенос всех авторских фракций и окончательная классификация относятся к S09. Это допустимое явное значение; произвольные неизвестные строки отклоняются.
- `attackSpeed` по-прежнему означает секунды между атаками; определения называют это `AttackIntervalSeconds`. Формулы боя, экономика, XP и сбросы похода не изменены. Максимальное HP боевого экземпляра учитывает уже существующие стартовые бонусы.
- Добавлены отдельные сборки runtime/editor/Edit Mode/Play Mode. Test Framework 1.7.0 закреплён явной зависимостью — эта версия уже находилась в локальном кэше проекта.

## Валидатор

Проверяет используемые игрой `Assets/Resources/Configs/Units.json`, `Abilities.json`, `Map.json`:

- пустые и повторяющиеся ID/старые ключи, имена, роли и фракции;
- здоровье, ступень, конечность чисел, диапазоны урона, положительную задержку атаки;
- ссылки на способности, портреты, снаряды, кнопки и изображения эффектов;
- размер отряда, размещение 1–6, повторяющиеся места и ID экземпляров;
- карты, следующие карты, типы и ID узлов, координаты, начало и выход;
- ссылки и дубликаты рёбер, составы встреч, достижимость узлов от старта;
- известные текущие финальные бонусы и специальный терминальный маркер.

Не валидирует будущую сюжетную кампанию с условиями и флагами. Поля `background` и `arena` в карте сейчас не используются проверенными загрузчиками; проверка этих ресурсов как обязательных не включена. Неиспользуемая копия `Assets/Configs/Map.json` не является источником runtime-данных.

Первый прогон выявил `InnerFire` у последней SwampMap: такого эффекта нет в ApplyBuffs. По текущему коду завершение последней карты сразу сбрасывает поход, поэтому маркер допустим только на терминальной карте и явно выводится как примечание. Использование его до следующей карты считается ошибкой. Его механику не придумывали; вопрос переносится в S03/S08.

## Запуск проверок

Из корня проекта:

```powershell
.\test-project.ps1
.\test-project.ps1 -Suite Validate
.\test-project.ps1 -Suite EditMode
.\test-project.ps1 -Suite PlayMode
.\test-project.ps1 -Suite EditMode -ProbeFailure  # ожидаемая ошибка: проверка самого runner
.\build-windows.ps1 -OutputDirectory 'Builds\S02\Windows'
```

В Unity: меню **Crusade → Validate Content**. Скрипт тестов создаёт отдельный каталог логов, проверяет ненулевое количество тестов, результат XML и код процесса; отсутствие XML не считается успехом. Есть ограничение времени 15 минут на этап. Перед запуском закрыть Unity Editor, если он уже открыл тот же проект.
